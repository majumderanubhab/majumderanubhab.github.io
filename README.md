# majumderanubhab.github.io

Personal academic website, built and published to GitHub Pages automatically on every push to `main`.

## Updating content

All content lives in plain YAML files in **`content/`**, one per section. You never need to touch the HTML, CSS or JavaScript.

| File | What it holds |
|---|---|
| `content/profile.yml` | Name, position, status, photo, bio, interests, contact details, profile links |
| `content/news.yml` | News on the Overview tab (newest first) |
| `content/research.yml` | Research thrusts: summaries, highlights, figures, linked papers |
| `content/publications.yml` | All publications |
| `content/experience.yml` | Research positions, teaching, education |
| `content/recognition.yml` | Awards and the photo gallery |
| `content/activities.yml` | Workshops, invited talks, summer schools, academic service |
| `content/network.yml` | Academic journey, co-author institutions and co-authors (map) |

Each file starts with a short comment explaining its fields, often with an example to copy.

### The easiest way: edit on github.com

1. Open the file on GitHub and click the pencil icon.
2. Copy an existing entry, paste it, and change the text. Keep the indentation (spaces, not tabs).
3. Click **Commit changes**. The site rebuilds and goes live in about a minute.

If something is wrong (a missing field, a paper id that doesn't exist, a photo that isn't in `images/`), the build stops, the live site stays as it was, and the **Actions** tab shows a message saying exactly what to fix.

### Common tasks

- **News:** add an entry at the top of `content/news.yml`.
- **New paper:** add it to `content/publications.yml` with a unique `id`, then add that `id` under the right thrust in `content/research.yml` (and, if you like, under its co-authors in `content/network.yml`).
- **New photo:** upload it to `images/` (on GitHub: *Add file → Upload files*), then add an entry to `gallery` in `content/recognition.yml`.
- **New job:** add it at the top of `positions` in `content/experience.yml`, and update `position` / `affiliations` / `bio` in `content/profile.yml`.

### New papers arrive by themselves

Every Monday, GitHub checks your ORCID (through OpenAlex). If it finds a paper that isn't on the site yet, it opens a **pull request** (Pull requests tab; GitHub also emails you) that already adds the paper to `content/publications.yml` and its co-authors and institutions to `content/network.yml`.

1. Open the pull request and read the summary at the top.
2. Add the paper's `id` under the right thrust in `content/research.yml`: open **Files changed**, then the file, then **Edit file**, or edit the file in the same branch.
3. Click **Merge pull request**. The site updates about a minute later.

Not your paper? Close the pull request and add its DOI to `content/import-ignore.yml`. To check right away instead of waiting for Monday: **Actions → Import new publications → Run workflow**.

### YAML in 30 seconds

```yaml
- date: Dec 2026          # "key: value", one per line
  text: My news item       # entries of a list start with "- "
  tags:                     # a nested list is indented by two spaces
    - first
    - second
```

Put a value in quotes if it contains `: ` or starts with a quote, `#`, `@`, `*` or `&`.

## Preview locally (optional)

```bash
pip install pyyaml          # once
python3 scripts/build.py    # builds data/content.js from content/ and checks it
python3 -m http.server 8000 # then open http://localhost:8000
```

## Files

- `content/*.yml`: **content** (edit these)
- `scripts/build.py`: checks the content, builds `data/content.js` and `references.bib` (both generated, not stored in git)
- `.github/workflows/deploy.yml`: runs the build and publishes the site
- `index.html`, `css/style.css`, `js/site.js`: page skeleton, styles and rendering
- `data/land.js`: map grid, generated by `scripts/build_land.py`
